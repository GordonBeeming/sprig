# Copy-on-write workspaces: initial design

## Evidence and decisions

The repository started with a blank README and no code. The [reference comparison](research/simgit-cowtree.md), [APFS/git-cow investigation](research/apfs-git-cow.md), and [Shunt history](research/shunt.md) pin the inspected revisions and distinguish source inspection from executed tests. No upstream source is reused.

Use the installed Git executable, minimum **2.43**. Git owns registration, refs, the index, attributes, checkout and hooks. Both [git2](https://docs.rs/git2/latest/git2/struct.Repository.html#method.worktree) and [gix](https://docs.rs/gix/latest/gix/struct.Repository.html#method.add_worktree) now expose worktree creation. Neither earns a dependency here: reproducing the user's Git configuration and hook/filter behaviour would increase the compatibility surface. The floor includes [`check-attr --source`](https://git-scm.com/docs/git-check-attr/2.43.0), [`cat-file -Z`](https://git-scm.com/docs/git-cat-file/2.43.0/) and [`git hook run`](https://git-scm.com/docs/git-hook/2.43.0). All CLI acceptance scenarios pass on installed Git 2.53 and an isolated build of Git 2.43.0; see the [verification record](verification.md).

Use `tool` for the executable and package. A library exposes the application operations so a later packager can ship the CLI beside MyTerm. No daemon or MyTerm changes. JSON schema major 1 and executable semver are separate: consumers reject unknown schema majors, ignore new fields, and negotiate through `capabilities --json`. stdout has one final result; progress/diagnostics go to stderr. Exit 0 means success, 2 invalid request, 3 unsupported, 4 conflict/busy, 5 operation failure/recovery required, 6 a valid workspace with configuration/cleanup attention or no shareable files. Post-mutation failures include structured recovery paths and argv.

## Creation

Default is detached source HEAD. `--detach [--ref]`, `--new-branch NAME [--ref]`, and `--branch EXISTING` are the three modes; `--branch` with `--ref` is invalid. Resolve commits and validate names before mutation. Never force a branch already checked out elsewhere.

Require a clean source: no staged, unstaged, conflict or non-ignored untracked paths. Ignored paths are a separate policy, initially `copy.ignored = "none"`. No dependency/cache directories or secrets are copied. Report the effective policy and origin. Source index bytes, HEAD and config remain unchanged; read-only commands disable optional index refreshes and `diff.autoRefreshIndex`.

Check source/destination volume identity and probe native cloning using disposable files on that volume, preferring common Git tool storage outside checkout contents. The destination must not exist and its parent must exist. Reject overlapping registered worktrees and Git metadata. Journal the operation, reserve the destination with an exclusive directory creation, and ask Git to register `--no-checkout`. Read the target tree into the new index. Materialise attributes first, clone eligible tracked source files with matching object IDs and actual target-filtered bytes, then use `checkout-index` for remaining paths. Reject seeding from ACL-bearing files or xattrs other than OS provenance, so private donor metadata is not copied. Refresh only the new index. Replay Git's post-checkout hook with the documented null old HEAD, new HEAD, branch-change arguments. Hook failure retains the valid workspace as partial success.

Do not clone directory trees, copy a source index, invent index stat data, reset the source or prune unrelated registrations. Failed/interrupted creation retains its journal and owned directory; recovery reports exact paths and commands. Explicit `--acknowledge-create` clears the tool journal while preserving the retained directory and refs. It does not repair or reset user state.

## Conversion and recovery

Discover registered donors in the same common repository. `--source` restricts discovery. Different commits are supported: index object IDs narrow candidates; BLAKE3 digests verify materialised bytes. Skip staged/unstaged paths, symlinks, hard-linked files, set-id/flagged files and unsupported types; reject an unmerged index. Preserve unrelated untracked/ignored paths and Git index bytes. Matching clone-group IDs are an advisory repeat-conversion skip, never a numerical claim of exclusive savings.

Take a nonblocking common-repository kernel lock, released on process death; stale diagnostic text does not keep a lock alive. Check ordinary Git lock files too. This coordinates cooperating instances only. Users must stop editors/builds/Git operations in donors and target. Capture identity, size, timestamps, permissions, ownership, flags, xattrs and ACLs; check them and bytes again around mutation. Reject symlink traversal. Residual races remain between checks and rename, and processes holding an old file descriptor can continue writing the replaced inode. This is an explicit idle-worktree contract, not a claim of process exclusion.

For each file, publish a complete journal atomically, naming the target and random sibling plus inode ownership. Native-clone the donor, checkpoint the clone identity, restore **target** metadata, verify the clone's bytes and metadata, and flush it. Persist the prepared identity before `RENAME_SWAP`. Swap atomically, flush the parent, then validate both installed clone and retained original before deleting the original. Journal removal follows cleanup. Recovery determines whether a swap occurred from inode identities, including termination between swap and checkpoint. A known uninstalled clone may be removed after validation; changed or unknown files remain for manual resolution. A crash between clone creation and its identity checkpoint requires inspection of that sibling. Metadata that cannot round-trip is skipped before publication. Durability or cleanup failures retain useful recovery state. Disk-full leaves the original at its old path or retained sibling; no blanket rollback/delete.

Use Darwin clonefile, copyfile metadata and rename-swap behind a narrow platform module. Native tests found that copyfile retained the donor's older birth time, so restore the target's birth time explicitly with `fsetattrlist`. Test ACL inheritance and xattr removal too, and skip metadata that cannot round-trip. Inode and ctime change by definition; parent directory timestamps may change. Preserve file mtime, birth time, atime, UID/GID, permissions, ACL and xattrs where verified. Access time is a preservation check, not an external-writer signal. No hard-link substitute and no full-copy fallback. Linux is an unsupported platform with a future interface seam.

Dry-run reads state and bytes only: no lock-file creation, probes, journals, config writes or exclusions. It reports native support as unprobed and candidate logical bytes as an upper bound, not reclaimable storage. Status and discovery never convert or migrate state.

## Configuration and backups

Read user config at `~/Library/Application Support/tool/config.toml`, then common-Git-directory `tool.toml`; command-line backup flags override both. Repository config is local administrator data, never executable instructions. Unknown keys/values fail closed. `config set --scope user|repository` writes atomically. Built-in `[backup] time_machine_exclude = true`. Initially `copy.ignored` accepts only `none`.

The installed macOS `tmutil(8)` documents default sticky exclusions, which follow moves and copies, without the root/FDA requirement of `-p` and `-v`. Apply only at the requested root, verify with `tmutil isexcluded -X`, and inspect the direct sticky xattr to distinguish inherited/pre-existing state. Never copy donor directory exclusion metadata. Record pending intent on the directory before applying an exclusion, then record its verified value. Removal requires completed provenance and matching metadata. Interrupted application with uncertain ownership needs explicit `backup apply --resolve-pending`; ordinary retry/removal cannot claim that exclusion. Other backup controllers must be idle, since the supported interface provides no atomic compare-and-set against them. Pre-existing and inherited exclusions are preserved. Disabling policy adds nothing and removes nothing. `backup apply|remove PATH` is the explicit retry/removal interface. Reject roots containing original checkouts or common Git metadata. Failure returns a valid-workspace partial result; never silently elevate privileges.

Excluded roots also exclude local uncommitted work. This does not remove historical backups or prevent local APFS snapshots. On other platforms the setting is not applicable. Exclusion verification does not depend on a configured backup disk.

## Initial support and verification

Support ordinary full worktrees, linked-worktree sources, detached/existing/new branches, SHA-1/SHA-256 through Git, UTF-8 paths including whitespace/newlines, symlinks through Git checkout, executable bits, and ordinary text/eol attributes when byte-verified. Reject sparse checkout/index, submodules and custom filters/LFS for creation; conversion skips modified files and rejects unsupported repository features before replacement. Non-UTF-8 names fail explicitly instead of lossy conversion. Further filter support needs its own tests.

Tests use disposable repositories with synthetic Git object fixtures. Native macOS tests exercise cloning, independent writes, ACL/xattr/timestamp fidelity, atomic swaps, exclusion provenance and move behaviour. Inject process exit and I/O failures at journal/clone/swap/cleanup boundaries; reopening must retain every pre-existing file. Check staged/unstaged/untracked preservation, index byte identity, external-change detection, contention/stale locks, branch combinations and structured outcomes. Format, clippy and tests gate review. A separate-model review is required before landing; this task authorises no commit or push.

Benchmark ordinary Git creation, CoW creation and conversion with elapsed time and `statfs` volume allocation changes. Include logical bytes and per-file allocated blocks only with their separate meanings. Use random materialised data, repeats and a background-noise control. APFS snapshots, delayed accounting and unrelated writes can obscure reclaimed space; report raw measurements and uncertainty. Reserve metadata space plus any changed checkout bytes; later independent writes can still fail ENOSPC.
