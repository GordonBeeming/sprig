This report verifies source and test assertions, not a fresh hardware run. ## Filesystem and metadata

On Darwin, [`cloneVolumeTree`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/fidelity_darwin.go#L46) calls native `Clonefile` with `CLONE_ACL`. Before cloning, it scans for ACLs, hard links and set-id files. The code documents two gaps encountered with recursive cloning: it splits hard links, and descendant ACLs need explicit restoration. Shunt reconstructs hard-link groups *within the destination*, restores ACLs, and restores parent directory timestamps changed by those repairs. It rejects set-id files and destination parents with ACLs that could change inherited permissions.

The Darwin [fidelity test](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/fidelity_darwin_test.go#L21) creates a regular file, a hard link, a symlink, a sparse file, an xattr, an ACL and explicit timestamps. Its comparison checks permissions, UID/GID, flags, apparent size, `st_blocks`, access/modification/birth times, symlink targets, xattrs and ACLs. Separate tests reject set-id files and ACL-bearing destination parents before leaving a clone.

Portable lesson: define metadata fidelity as a tested contract. A successful clone syscall alone does not prove it. For conversion, the new inode must carry the target's metadata, even when the donor has different metadata. Rejecting or skipping unsupported metadata is safer than claiming full preservation. Existing hard links in a target deserve an explicit policy; making cross-worktree hard links would break write independence.

The non-Darwin [implementation](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/fidelity_other.go#L12) invokes `cp -a --reflink=auto`. That permits full copies. It does not establish Linux CoW support suitable for this tool's mandatory-clone contract. Shunt also does not provide a source/destination capability probe in this clone path.

## Publication, interruption and cleanup

[`CloneVolumeSetResult`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/clone.go#L921) stages the complete declared volume set under the destination's parent. It validates each volume before publication. An absent destination is installed by rename; an existing root is installed with Darwin [`RENAME_SWAP`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/rename_darwin.go#L7). The old root remains at the stage path until removal succeeds. Results retain `Committed` and exact `RecoveryPaths`, so a post-install cleanup failure cannot be confused with an unchanged destination. [Tests inject cleanup failure](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/clone_test.go#L652).

The higher-level [baseline manager](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/databaseline/baseline.go#L516) publishes immutable generations and an atomic manifest. It flushes regular files and directories; Darwin file flushes use `fsync` followed by [`F_FULLFSYNC`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/databaseline/fullsync_darwin.go#L11). A failure after manifest rename reports committed-but-durability-unconfirmed. Operation IDs let a committed retry return the earlier generation without taking another snapshot.

The [crash test](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/databaseline/baseline_test.go#L765) spawns a process and exits at generation installation, manifest staging, manifest rename and publication. Reopening must retain the correct rollback predecessor. This test substitutes a regular copy for native cloning: it verifies recovery state transitions, not APFS clone behaviour or power-loss durability. Other tests cover capture failure preserving the current baseline, cancelled commit reporting committed, reset cleanup failure, leased generations during concurrent promotions, and lifecycle restoration after failure.

Portable lesson: record ownership and the commit point before replacement. Return useful recovery paths on disk-full, flush or cleanup errors. Test actual process death, including the gap after a filesystem mutation but before its journal checkpoint. A temporary file is not itself a recovery protocol.

The low-level [`CloneVolume`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/clone.go#L856) clears an existing destination before cloning. Its comment explains that `cp -c -R` previously nested the source beneath an existing destination. That deletion relies on Shunt's ownership of disposable volume clones and must not be carried into conversion of user-owned files. The full volume-set staging protocol provides the stronger replacement boundary.

## Locks and external writers

Shunt uses kernel `flock` locks in a documented project, siding, state order. Project-exclusive changes block lifecycle work; different sidings can share the project lock while taking separate siding locks. [`operation.go`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/siding/operation.go#L35) reports waits after a grace period and includes a restricted holder record. Kernel locks release on process death; a leftover record is diagnostic evidence rather than proof that its PID still owns a lock. [Tests](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/siding/operation_test.go#L20) cover serialization, cancellation, parallel sidings, lock permissions, stale records and record clearing.

Baseline generation leases keep a generation alive while another operation clones from it. Cleanup acquires an exclusive lease and runs outside the manifest mutation lock. [Tests cover this overlap](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/databaseline/baseline_test.go#L713).

These locks coordinate Shunt processes. Database snapshot consistency comes from the separate [`PromoteWithLifecycleOperation`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/databaseline/baseline.go#L316) contract: quiesce the app, stop all volume consumers, sync, snapshot every declared volume, publish, then restore the previous lifecycle state. The Git tool cannot infer that an editor or build has stopped from its own lock. It needs before/after identity checks and an explicit residual-race statement.

## Concrete fixes in history

- [`6f52cff0`](https://github.com/GordonBeeming/shunt/commit/6f52cff0f1166a8ef1c3a073054e524d26b449c0) replaced the earlier `cp -c -R` Darwin path with native cloning and fidelity repair, added immutable generations, leases and durability tests, and distinguished committed rollback durability failures. The parent revision and current source verify that change. Its squashed history gives no separate incident report for every metadata case, so the tests establish the requirements without proving a particular production incident.
- [`5d0b3f2e`](https://github.com/GordonBeeming/shunt/commit/5d0b3f2e7c98512fb1ccc8fab9ff2049f97b9b14) made removal journalled and crash-safe. Its message records a concrete batch-removal bug: one siding checked out another selected siding's branch, and removing the first deleted the second's ref. Ownership checks now reject that collision. The same change uses exact worktree removal instead of repository-wide prune, preserving unrelated recoverable registrations. [Tests](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/clone_test.go#L373) cover unregistered destinations, unrelated stale registrations, quarantine restoration and cleanup failure preserving usable Git metadata.
- [`3d9bdaa5`](https://github.com/GordonBeeming/shunt/commit/3d9bdaa5349b024da989a252f00392687be702b9) explains why lock waits need diagnostics: a long guest command held the siding lock, and even `logs` queued silently behind it. Review also found that full argv in the holder record could reveal secrets to waiters; the final code records only binary and subcommand. Keep progress on stderr and restrict diagnostic data in this tool too.

## Measuring sharing and writes

[`storage.Filesystem`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/storage/size.go#L88) reports volume capacity through `statfs`. Directory scans deliberately report logical bytes and mark overlapping/shared content; [`LogicalSize`](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/storage/size.go#L116) never calls that reclaimable space. The [README](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/README.md#L120) reserves Apple-container reclaimability for the runtime's official report.

The native fidelity test compares `st_blocks`, which checks sparse allocation shape but does not prove shared physical extents. Shunt has timing [benchmarks](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/fsclone/fidelity_darwin_test.go#L364) comparing its fidelity path with raw `clonefile` over 10,000 tiny files; no measured results are claimed here. Its hardware-gated [data lifecycle integration test](https://github.com/GordonBeeming/shunt/blob/4c90f3251ba969fa3f1a011dc51b1d1a1be2720e/internal/siding/data_darwin_test.go#L19) writes a second value to the source after promotion, rolls back, and expects the first value from the retained generation. That is evidence of intended write independence, not a full two-way write-isolation or physical-savings benchmark.

For this tool, use disposable APFS trials with volume allocation observations before and after ordinary checkout, cloning, conversion and writes. Report background-write noise and snapshot retention. Per-file allocated blocks and logical candidate bytes remain useful measurements with different meanings.

## Scope carried forward

Adopt native clone-or-error semantics, metadata fixtures, staged atomic replacement, explicit committed/recovery outcomes, kernel lock ownership and crash tests. Preserve only paths and refs the current operation demonstrably owns. Treat donor content and mutable external processes as separate safety concerns.

Database-wide quiescence, stopping Docker consumers, immutable baseline generations, guest restore state and rollback of a complete volume set are specific to Shunt. A Git conversion preserves each existing file and index rather than replacing an environment from a canonical generation. Shunt provides no inspected Time Machine integration or Git-file deduplication algorithm, so those still require separate research and tests.
